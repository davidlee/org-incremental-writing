### Cited facts
1. **Entry struct / outline context.** `org-iw-entry` = `id title file memberships` only (org-iw-core.el:48-54); no outline path or heading context captured today. Title = `org-get-heading t t t t` for a heading, `#+title`/file basename for the document entry (org-iw-discovery.el:199-206) — raw, links not reduced. Discovery scans every file in a temp buffer with `org-mode` enabled (`delay-mode-hooks`) (org-iw-discovery.el:311-317) — visited and unvisited files alike, because `--insert-text` copies a live buffer's whole widened text or `insert-file-contents` (:284-299). So `org-get-outline-path` is available during the scan at no extra I/O. (exp) In a `delay-mode-hooks` temp buffer `(org-get-outline-path)` returns `("Top" "Mid")`, with WITH-SELF `("Top" "Mid" "Leaf")`. Cost: O(depth) `org-up-heading-safe` per entry; USE-CACHE is valid (org.el:7860-7882, org 9.8.10) since the scan visits entry starts in increasing order (forward regexp search + `seen` list, org-iw-discovery.el:264-276) — needs `org-outline-path-cache` bound nil per buffer. `org-get-outline-path` strips statistics cookies and shows link descriptions (org.el:7836-7846) — inconsistent with the raw title. Document entry has no ancestors (`org-up-heading-safe` → nil). Adding a struct field is non-breaking for tests: discovery tests project entries to `(ID . MEMBERSHIPS)` (test/org-iw-discovery-test.el:51-55) and core tests build with keyword args (test/org-iw-core-test.el:37).
2. **Delete via the write path.** `org-iw-write-put-rank` = type checks → `--preflight` (modtime, writable, read-only, expected lines, unrecognised drawer) → `--apply` (`atomic-change-group`, save-if-was-clean, returns `saved`/`unsaved`/`(save-failed . E)`) (org-iw-write.el:126-135, :59-97). Preflight with an integer EXPECTED already refuses duplicates and `IW_<Q>+` (`--expected-p`, org-iw-write.el:48-57), so a delete verb can reuse it verbatim and pass a different lambda to `--apply`. `org-entry-delete` (org.el:13431-13450) loops over all lines matching `PROP\+?` — it removes duplicate keys and accumulate lines alike (exp). Empty drawer: `org-entry-delete` removes the drawer when it becomes empty (org.el:13443-13446); (exp) `* H\n:PROPERTIES:\n:IW_A: 1\n:END:\nBody` → `* H\nBody` on both org 9.8.10 (Emacs 31) and org 9.7.11 (Emacs 30); same for a document-level drawer. In practice never empty: a member must have an ID (org-iw-discovery.el:221), and the ID line is in the same drawer. **Key matching follows `case-fold-search`**: the regexp from `org-re-property` (org.el:6038-6062) binds no case; with `case-fold-search` nil, `:iw_a:` is NOT deleted and returns nil (exp). Discovery reads keys case-insensitively (org-iw-discovery.el:148-150, org-iw-core.el:85), so the delete lambda must bind `case-fold-search` t. (Contrast: `org-entry-put` matches case-insensitively regardless and rewrites `:iw_a:` to `:IW_A:` (exp).) Undo: one undo after an `atomic-change-group` delete restores the line (exp), matching existing undo tests (test/org-iw-write-test.el:147-170).
3. **Ties / move / explicit depth.** Order by rank then `string<` ID (org-iw-core.el:117-128). `rank-at` returns nil unless neighbours differ by >1 (org-iw-core.el:182-183): two tied neighbours always give `no-gap`. (exp, order x(0) a(1024) b(1024) c(1024)): c up to depth 2 → `(no-gap 2)`; a down to depth 2 → `(no-gap 2)`; c to front → `(moved 0 -1024)` (ends always have room). Explicit depth already exists: `(after N)` is `min(N, count)` (org-iw-core.el:164) — exact for N in [0, count], only clamps beyond (exp: `(after 99)` with 3 others → 3). Depth counts *others* (order minus target) (org-iw-core.el:202-203). So: up = `(after (1- i))`, down = `(after (1+ i))`, before X = `(after j)`, after X = `(after (1+ j))`, where i = target's index in ORDER and j = X's index in ORDER-minus-target. `core-place` reports `unchanged` by `eq` position (org-iw-core.el:204); `core-reorder` gives the new order (:210-215). No redistribution: gap-zero refuses via `org-iw--refuse-no-room` (org-iw.el:189-193) — matches ADR-004.
4. **Session.** `org-iw--session` = `queue id title` (org-iw.el:304-307); set only by `--session-start`, cleared only by `--session-end` (:309-349). `org-iw--visit (scan entry queue pos total)` resolves (refuses first if unresolvable), `pop-to-buffer-same-window`, widens only if needed, reveals, starts session, reports (org-iw.el:453-472) — view-open should call it with the row's ordinal as POS. Continue finds the session entry by ID in a fresh scan (org-iw.el:575-578): if moved within the queue → unaffected; if removed → next Continue refuses "%s is no longer in queue %s" (:505-514), session stays in the mode line until ended. Session title is a snapshot at visit time (:335).

### Naming precedents
- Public `org-iw-<layer>-…` (`org-iw-core-`, `org-iw-discovery-`, `org-iw-write-`) or plain `org-iw-…` in the command layer; private `org-iw-<layer>--…` (`org-iw--` in org-iw.el); a `--` symbol is file-private (STD-004 item 2).
- Write verbs: `org-iw-write-put-rank` (verb-object). A delete sibling would naturally be `org-iw-write-delete-membership` / `-remove-membership`.
- Struct constructors `…-create` with `(:copier nil)` (org-iw-core.el:48, org-iw.el:304).
- No mode/keymap precedent in repo. Emacs convention: `define-derived-mode org-iw-view-mode tabulated-list-mode` → `org-iw-view-mode-map`; a `list-FOO`-style entry command (tabulated-list.el:836-866 docstring), e.g. `org-iw-view` / `org-iw-list-queue`, `;;;###autoload`'d like commands at org-iw.el:394.
- Layout: ADR-003 (`doctrine show ADR-003`) — four layers, core ← discovery ← write ← "Commands and view"; "Layers map to files". View belongs to layer 4. STD-004 item 1 enumerates exactly four files; a new `org-iw-view.el` needs STD-004 amended or the view kept inside org-iw.el (see Risk 1).

### Risks / sharp edges
1. **View file placement vs privacy rule.** The view needs `org-iw--scan`, `--visit`, `--order`, `--read-queue`, `--put-rank`, `--session`, `--report` (org-iw.el:145-600). Under STD-004 item 2 a separate org-iw-view.el cannot use `--` symbols → either make them public or keep the view in org-iw.el. Separate file would also need `require 'org-iw` while org-iw.el autoloads the view — avoid circular require. STD-004 item 1 also fixes the file list at four.
2. **Delete is case-sensitive unless bound.** `org-entry-delete` silently no-ops on `:iw_q:` if `case-fold-search` is nil (exp). Bind it t in the delete lambda and assert the result non-nil (preflight has already confirmed the line exists).
3. **Ties block moves.** Moving between two equal-rank neighbours → `no-gap`, no redistribution (org-iw-core.el:182-183; exp). Up/down past a tied pair will refuse with "no room…" (org-iw.el:189-193). Ends always work.
4. **Point jumping on refresh after remove.** REMEMBER-POS loses the row when its id vanishes → point to top (tabulated-list.el:508). Remove should pick the next row's id itself before reprinting.
5. **Stale rows.** Row data comes from an earlier scan; the safe pattern is rescan-per-action, find by ID, write with fresh rank as `:expected` — otherwise preflight refuses "IW_%s changed since scan" (org-iw-write.el:74-76), which is correct but confusing after an undo in the source.
6. **No auto-refresh.** The view won't refresh when source buffers change (undo included); refresh = rescan, which does pick up unsaved buffer text (org-iw-discovery.el:291-296). User must `g`.
7. **Open replaces the view.** `org-iw--visit` uses `pop-to-buffer-same-window` (org-iw.el:463), so opening from the view replaces it in its window. Decide whether to keep or use another window.
8. **Session after remove.** Removing the session's entry leaves a dangling session (mode line still shows it; next Continue refuses, org-iw.el:505-514). Design must choose: end session, visit next, or refuse.  Moving within its queue is harmless.
9. **Outline text vs title inconsistency.** Outline path strips cookies and shows link descriptions; title keeps raw links (org-iw-discovery.el:204 vs org.el:7836-7846) — pick one rendering for the view. COMMENT ancestor also stripped by outline path (org.el:7847-7848).
10. **Delete removes accumulate lines too.** `org-entry-delete` deletes `IW_<Q>+` lines as well (org.el:13438-13442) — safe only because preflight with integer EXPECTED refuses those shapes (org-iw-write.el:53-57). Keep preflight mandatory on delete.
11. **No undo in the view.** `buffer-undo-list` is t in tabulated-list buffers (tabulated-list.el:871) — undo must happen in the source buffer; this is why refresh-after-undo is in scope.
12. **Row id must be the Org ID, not the struct.** `equal` on entry structs compares all fields; a changed rank would break REMEMBER-POS (tabulated-list.el:521).
