# RFC-001: org-iw delivery roadmap

## Context

PRD-001 (`doctrine spec show PRD-001`) fixes what org-iw must do. This RFC
settles how delivery is sequenced: the slice order, what each slice
proves, and when governance documents arrive.

Forces:

- **Working software first.** Every slice ends in something the user can
  run and trial in their own Emacs (candidate P3 below).
- **No up-front pontification.** Governance lands just in time, when the
  next piece of work would benefit from it.
- **Layering is structure, not sequence.** The brief's four layers become
  the code's module boundaries (candidate A4 below). Delivery cuts through
  them vertically.

## Discussion

### Slice sequence

Seven vertical increments, SL-001 to SL-007 in table order. Each one names the PRD requirements it
satisfies, fully or partly, and the PRD-001 open questions it must settle.

| # | Slice | Delivers (trial-able) | REQs | Settles |
|---|---|---|---|---|
| 1 | **Walking skeleton** | Configure one queue. Add the heading at point (append). Visit next. Continue to End. Includes tooling (Makefile, ERT runner, lint, Emacs 30 in flake), the minimal ordering core, discovery over configured files, a single-property write, and the save policy. Minimal safety: refuse to write on duplicate IDs or invalid ranks. | 001, 003, 004, 005, 006, 008, 011 (heading, append), 014, 015 (End only), 021, 022, 023, 024, 025 | OQ-1 (rescan acceptable for now?), OQ-4 |
| 2 | **Placement and vocabulary** | Fixed, fractional and end placement. Per-queue labels and default. Continue chooser. Messages for empty, singleton, missing-target and no-op cases. | 3 | **Queue view and membership ops** | Inspect a queue (list view): open, up/down, before/after, remove, refresh. Move and remove from the source entry, with a queue prompt when ambiguous. | 013, 017, 018 | — |
| 4 | **Documents and batch add** | Document targets (file-level drawer, explicit document add). Batch add of files in canonical path order with a report. Journal corpus becomes usable. | 002, 011 (document), 012 | OQ-2; revisit OQ-1 at corpus scale |
| 5 | **Identity and diagnostics** | Refiled entries resolved by ID. Actionable diagnostics for duplicate IDs, invalid ranks, invalid queue IDs and unresolvable targets, with locations. | 007, 008 (ties hardened) | — |

Dependencies: 1 → 2 → 3. Slices 4 and 5 need only 1 and may run
alongside 2 and 3. Slice 6 needs 2 (placement) and 3 (move). Slice 7 is
last.

Rejected: the layered 9-slice plan (ordering core, discovery, mutation,
commands, session, view, batch, redistribution, docs). It gives nothing to
trial until slice 4 or 5 and invites building infrastructure ahead of need.

### Governance candidates

Each is drafted when the work that first needs it begins. Titles load in
every agent's context; bodies are consulted during design.

**ADRs**

- **A1 — Queue state lives on the entry.** Membership and rank are
  `IW_<Q>` properties on the entry, and queue views are derived. No queue
  file, database, index or log is authoritative. A cache is only a
  disposable copy. Rejected: a managed queue file (mir.el), an org-roam
  database, a separate state file. Sources: PRD §3, REQ-001, REQ-025.
- **A2 — Sparse integer ranks with explicit redistribution.** Exact integer
  ranks; a move rewrites only the moved entry. When no gap is left, the
  whole queue is redistributed, only as user-approved maintenance.
  Rejected: renumbering on every move (bjsi's scheduler), floating-point
  ranks, fractional indexing. Sources: REQ-010, REQ-019, REQ-023.
- **A3 — Writes go through the file's open buffer; single writer.** The
  live buffer is authoritative. Save a buffer that was clean before the
  operation; leave an already-modified one unsaved. Nothing writes behind a
  live buffer. No transactions or rollback; recovery is Git. Sources:
  REQ-006, REQ-020, REQ-021, REQ-022.
- **A4 — Four layers with a fixed dependency direction.** Pure ordering
  core ← discovery/resolution ← Org mutation ← commands/view. The core
  touches no buffers and no Org. Source: brief § Implementation freedom.
- **A5 — Platform baseline** (Emacs 30.1, bundled Org, no runtime
  dependencies, `org-iw` prefix). **Not an ADR:** PRD-001 § 4 constraints
  carry it. Promote it only if the baseline is contested.

**Policies**

- **P1 — Lint and test gate.** Lint after every file change: byte-compile
  with warnings as errors, checkdoc, package-lint, zero warnings. ERT
  passes on Emacs 30 and 31. TDD red/green/refactor. Tests check behaviour,
  not trivial implementation. No phase closes red or with warnings.
- **P2 — One implementation per concept.** Search for an existing owner
  and adapt it before writing new code. Duplicated or parallel logic is a
  blocking review finding. A replaced path is deleted in the same change.
  No speculative abstraction.
- **P3 — Working software, verified by human trial.** Every slice delivers
  a runnable increment and ends with a human-verified check: a short trial
  script the user runs. A slice doesn't close without the trial.
  Infrastructure is built only as far as the current increment needs.

**Standards**

- **S1 — Elisp and test conventions.** `lexical-binding`; `org-iw-` public,
  `org-iw--` private; docstrings; files split by the A4 layers. Tests run
  against temporary Org buffers and files through shared fixture helpers,
  not mocks of Org. Indentation follows Emacs's standard `lisp-indent`.
  Written from conventions established in practice, not in advance.

### Governance schedule

| When | Documents |
|---|---|
| Before slice 1 design | A1 → ADR-001, A3 → ADR-002, A4 → ADR-003, P1 → POL-001, P2 → POL-002, P3 → POL-003 (drafted 2026-09-30) |

## Outcome

Open. The slice sequence and governance schedule were agreed with the user
on 2026-09-30. This RFC resolves once the slices exist and the
"before slice 1" governance documents are drafted. Later re-sequencing
amends this RFC.

Progress: SL-001 to SL-007 created 2026-09-30 with `needs` edges matching
the dependencies above; ADR-001 to ADR-003 and POL-001 to POL-003 drafted.
